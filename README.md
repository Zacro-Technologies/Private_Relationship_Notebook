# Keepsake — Private Relationship Notebook

Keepsake is a native, local-first SwiftUI notebook for iPhone and Mac. It helps someone remember useful relationship context, find the right person offline, choose a gentle next connection, prepare a message without sending automatically, and record only outcomes the user can truthfully confirm.

The product source of truth is [Private_Relationship_Notebook_Specification.md](Private_Relationship_Notebook_Specification.md).

## Implemented application

- Adaptive iPhone tabs and Mac sidebar navigation, four-step onboarding, English/Japanese app locale selection, Dynamic Type-friendly native controls, keyboard-accessible Mac forms, and privacy-curtained app locking with device-owner authentication.
- A complete Add Hub for people, interactions, private notes, reminders, commitments, photos/screenshots, documents, supported archives, and profile/QR exchange. Mac also has Command-K local quick open, capture shortcuts, drag/drop, and independent person/import/profile windows.
- Local Core Data uses three stores: a private relationship vault, structurally separate owned-profile snapshots, and rebuildable device-local derived data. The account-bound cloud replica keeps the two synchronized entity families in one private CloudKit-backed store plus one local-derived store; Core Data rejects assigning the same CloudKit container identifier and database scope to multiple stores. The UI reads and writes the local replica and remains usable offline.
- People with multiple names, pronunciation, aliases, contact methods, relationship boundaries, clearly separated conversation-safe context and manual-only private notes, cadence, archive/restore, 30-day Recently Deleted recovery, explicit merge preview, and recoverable merge events.
- Structured contexts and nested contexts, cohort schemes and cohorts, dated memberships and assignments, role definitions and assignments, education enrollment, expected versus actual graduation, typed sourced assertions, and contextual relative-cohort descriptions.
- Typed custom-field definitions with validation and independent search, filter, sort, reminder, AI, mention, notification, and sharing policies. Credential-like fields are blocked and redirected to a password manager.
- Local Japanese/English search normalization, privacy-preserving match reasons, full canonical/custom-field facets, include/exclude groups, date/confidence/known-state ranges, graduation and custom sorts, portable saved views, stable paging, checksummed index persistence, and atomic rebuilds.
- Explainable weighted-random nudges with hard do-not-contact/never-suggest exclusions, archive and snooze rules, account-scoped exposure history, per-person cooldowns, rolling seven-day budgets, quiet hours, saved-view pools, configurable proactive local-notification frequency, manual “Surprise Me,” and stale-suggestion invalidation. Proactive payloads never preselect or identify a person; selection happens from current data only after an unlocked tap.
- Honest communication handoff for saved channels. Drafts can be copied or handed to another app, but Keepsake never equates opening a composer with sending or delivery; the user confirms the outcome.
- Interaction history with group participants, direction, exact or approximate dates, evidence-backed outcome states, content-fidelity labels, recap, commitments, follow-up, metadata/summary/full-transcript retention boundaries, and private reflection.
- A unified Today attention inbox for reminders, commitments, interaction follow-ups, pending import reviews, and unresolved handoffs, plus a private weekly reflection that does not score or gamify contact volume.
- Review-first pasted-text, text-file, PDF, and image import. PDF/image text extraction and Japanese/English OCR stay on device; source text is treated as untrusted; reviewers can edit facts, split/combine candidates, inspect exact source locations, and retain only approved evidence. Accepted people, provenance, artifact units, evidence, and assertions commit together.
- An iOS Share Extension accepts text, links, screenshots, images, PDFs, and documents into a complete-file-protected App Group inbox. It enforces 20-item/100 MB limits and creates no notebook record; the app moves each item into its protected local inbox only after onboarding and App Lock are clear, then presents the same explicit import review used by Open In and drag/drop.
- Version-aware, bounded JSON inspection with creates, non-overwriting updates, conflicts, identity/reference errors, unknown-field preservation, explicit preview, and idempotent stable identifiers. Exports support full-vault, selected-person, saved-view, or self-profile scopes with privacy-minimized referential closure.
- Plaintext and password-encrypted `.relationshipvault` import/export with validated canonical notebook data, bounded metadata-stripped JPEGs, strict cardinality/path/MIME/hash/reference checks, and protected staging that rolls back if the reviewed transaction fails.
- Deliberately separate Create Card, Received Profiles, and Saved Versions workspaces with five sender presets, field allowlists, opt-in sanitized portraits, QR/file exchange, review-before-save exact outgoing copies, compare/reshare/archive history, advisory expiry, and clear non-revocation limits. Received `.keepsakeprofile` files get strict byte validation, field-by-field conflict review, explicit create-or-match choice, source attribution, scoped supersession, and idempotent transactional import without replacing manual facts or private notes.
- Reminder and commitment editors, recurrence metadata, proactive one-shot nudge scheduling, local notification authorization, quiet-hour adjustment, foreground presentation, serialized/capacity-bounded reconciliation, and notification-tap routing. Explicit reminders open the matching person; proactive nudges open Today and resolve the current eligible pool after unlock. Generic lock-screen copy is the default; names require both global and per-reminder opt-in, while sensitive context stays out of system payloads and preference keys.
- User-managed recommendation context for conversation topics, current priorities, connection preferences, boundaries, and support ideas. Every memory has an independent mention boundary and an explicit **Allow my Keepsake ChatGPT Shortcut** permission. Legacy permissions from older on-device or native-PCC experiments are never reinterpreted as Shortcut consent.
- One central AI workflow on iOS/macOS 26 or later: a required user-configured Apple Shortcut whose **Use Model** action is set to **Extension Model (ChatGPT)**. Authenticated App Intents and a protected, ten-minute, one-use handoff carry only an opaque request code in the URL. Personalized recommendations and contact-draft generation use this path; deterministic suggestions and manual editing are non-AI baselines, not competing model routes.
- A live non-personal challenge test must return the exact random response through Keepsake’s authenticated Get/Return actions before the connection is marked ready. This validates the protected transport, not **Use Model**, the selected Extension Model/ChatGPT route, account mode, intervening actions, processing location, retention, quota, or history; Apple provides no supported API for Keepsake to prefill or inspect the editable composite Shortcut.
- Account-isolated private iCloud synchronization for notebook records and sanitized portraits, with system-managed silent CloudKit pushes, ephemeral APNs registration diagnostics, local/offline editing, persistent-history reloads, durable permanent-deletion and whole-vault generation controls, device-local edit-versus-delete recovery drafts, truthful aggregate health, explicit Apple Account switching, and a protected review-first local-to-iCloud move that also carries Recently Deleted records.

## Project layout

- `Sources/RelationshipCore` — portable domain rules, persistence, search, import, nudge, communication, notification, sync, archive, consent projection, and protected AI-handoff services.
- `Sources/RelationshipNotebookApp` — the shared SwiftUI iPhone/Mac application.
- `ShareExtension` — the bounded, localized iOS Share Extension and its protected App Group handoff manifest.
- `Sources/RelationshipLegacyIntelligence` — compile-guarded native-model prototype code used only by a non-product regression-test target; it is absent from the app and exported core library.
- `Resources` — English/Japanese localization catalogs, privacy manifest, and entitlement templates.
- `Tests/RelationshipCoreTests` — production-core invariants, architecture membership, persistence, import, search, merge, archive, privacy, and localization tests.
- `Tests/RelationshipLegacyIntelligenceTests` — isolated regression coverage for the non-product historical router prototype.

## Open and run

Open `RelationshipNotebook.xcodeproj` in Xcode, select the **Keepsake** scheme, then choose a Mac or iPhone Simulator destination.

Command-line verification:

```sh
swift test
xcodebuild -project RelationshipNotebook.xcodeproj -scheme Keepsake \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project RelationshipNotebook.xcodeproj -scheme Keepsake \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

The Swift package exports only `RelationshipCore`. Its legacy intelligence target is test-only and not a package product; the Xcode project builds the complete app without those sources, embeds the iOS Share Extension, and embeds the production resources.

### Profile sharing and private notes

Open **Profile Sharing** from the Add screen, the Mac sidebar, or Settings. Choose a preset or individual fields, enter only the values you want to disclose, and select **Review what will be shared**. Nothing is persisted at that point. In the exact preview, select **Save this version and enable sharing**, then use the system share sheet for AirDrop, Messages, Mail, or another app. The recipient gets an independent `.keepsakeprofile` file, never access to the notebook; a later card cannot retract an earlier copy.

To receive a card, open **Profile Sharing → Review a shared profile file…**. Keepsake validates the exact file, labels it self-asserted and unverified, lets you deselect fields, and requires either creating a new person or explicitly choosing an existing one. Accepted values appear under that person’s **Facts & provenance** and cannot silently replace their local name, contacts, manual facts, safe-to-mention context, or private note.

A private note is a manual memory aid—for example, where you met, a detail to verify, or context you do not want suggested in a message. It is excluded from ordinary search, suggestions, AI drafts, notification previews, and profile cards. It does synchronize with the private notebook when iCloud is enabled and is included in full-vault backups and person-scoped exports. Keepsake rejects newly entered credential-like private-note content; passwords and authentication secrets belong in a password manager.

### Personalized recommendation context

Open a person’s profile and choose **Add** or **Edit** in **Recommendation context**. The five guided memory areas are intentionally separate from private notes. For each area, choose **Do not use with ChatGPT** or **Allow my Keepsake ChatGPT Shortcut**, and separately decide whether the fact may be mentioned in a proposed conversation idea. A boundary can therefore shape an in-app recommendation without being repeated as something to say. Permissions saved for older native-model experiments are shown as legacy and excluded until the user explicitly grants Shortcut access.

On **Today**, Keepsake chooses an eligible person locally using the normal do-not-contact, snooze, pool, cadence, and cooldown rules. **Personalize with AI** sends only the exact displayed, Shortcut-authorized memory items through the central workflow after confirmation. Contact-draft generation uses the same connection and separately previews its recipient name, current template, and authorized mentionable facts. If setup is incomplete, the action opens setup. If a request is cancelled, expires, changes context, or returns unusable output, the deterministic suggestion or editable draft remains unchanged. Private notes, contact addresses, interaction recaps, transcripts, and reflections are structurally excluded.

### Central Keepsake ChatGPT connection

On an Apple Intelligence-compatible device running iOS or macOS 26 or later, Apple’s Shortcuts app has a **Use Model** action whose **Extension Model** option uses ChatGPT. This configured Shortcut is Keepsake’s required and only generative-AI route. Apple’s documented URL scheme can open a blank Shortcut editor or open and run an existing Shortcut, but it cannot prefill or inspect a composite action chain. Keepsake therefore guides the unavoidable edits, verifies only the protected round trip, and always labels returned output **model, account, and actions not verified**.

Open **Settings & Privacy → Keepsake ChatGPT → Keepsake ChatGPT Connection** and use the compact guided setup:

1. Review and acknowledge what the connection test can and cannot verify.
2. On iPhone, tap Apple’s **Keepsake shortcuts** button. Keepsake copies a non-personal builder prompt; paste it into **Describe a Shortcut**. If that Shortcuts feature is unavailable, choose **Use Blank Editor and Copy Name** instead. On Mac, use the blank-editor button. In either case, keep the exact name **Keepsake ChatGPT Connection**.
3. Review the generated workflow—or manually add—and preserve these three actions in order:
   1. **Get Prepared AI Request** — set **Request Code** to **Shortcut Input**.
   2. **Use Model** — use the prepared AI request as input, select **Extension Model (ChatGPT)**, turn **Follow Up** off, and select **Text** output.
   3. **Return AI Result** — set **Request Code** to the original **Shortcut Input** and **AI Result** to the **Use Model** response.
4. Return to Keepsake and choose **Verify Connection**. Keepsake polls continuously and detects the exact protected test response automatically.

**Shortcut Input** is the input variable that Shortcuts supplies when Keepsake runs the Shortcut; it is not a fourth action. The standard guided path keeps the exact default name above. **Advanced** contains the same manual action checklist and the custom-name workflow for someone who needs a different name; the name saved in Keepsake and the name in Shortcuts must match exactly.

**Transport-only verification:** “Connected” means only that Keepsake’s authenticated Get/Return actions returned the exact challenge. It never means that **Use Model** or ChatGPT executed.

The connection test contains no notebook data and marks the transport ready only if the exact random challenge returns through Keepsake’s authenticated Get/Return transport. The transport verification expires after 30 days or immediately when the saved Shortcut name changes, after which the app requires another protected test. Because the workflow remains editable, Keepsake still tells the user to review its actions before every private request. Before every real run, Keepsake shows the exact context and asks for confirmation. The prompt is held in an atomic, backup-excluded cache file with complete iOS file protection and owner-only permissions; it expires after ten minutes and is deleted on cancellation or atomic result consumption. The URL contains only a random one-use code. Both Keepsake actions require local-device authentication. Inputs and results have independent character and UTF-8 byte limits and are rechecked against the current task and context. The test does not prove that **Use Model** ran, that **Extension Model (ChatGPT)** remained selected, which ChatGPT account mode was active, which extra actions ran, where processing occurred, what was retained, whether history was saved, or what quota applied.

The ChatGPT extension must be available for the user’s hardware, OS, language, and region, and Apple says the user must be at least 13 or the minimum age required in their country. Keepsake requires neither an OpenAI API key nor a ChatGPT account. A user may enable Apple’s ChatGPT extension without an account or sign in to an existing account; Keepsake cannot detect or attest which choice is active.

Every real handoff discloses that the selected contact name, approved recommendation context, draft text, and/or separately approved source excerpt shown in the preview will be sent to ChatGPT/OpenAI through Apple’s Extension Model, along with limited request metadata Apple describes. According to Apple, account-free extension requests are not tied to the user’s Apple Account and OpenAI must not store the request or response or use it to train models except where legally required. When the user is signed in, their ChatGPT account settings and OpenAI privacy policies apply, and requests may be saved to ChatGPT history. Keepsake cannot verify these provider-side conditions, so users should review their Apple Intelligence and ChatGPT settings and omit any context they do not want transferred.

### Password-encrypted archives

Keepsake can import and export password-encrypted `.relationshipvault` files. The validated plaintext package is placed inside an authenticated encrypted envelope; decryption validates the complete envelope and then re-runs the normal `.relationshipvault` package checks before presenting an import review.

The version-one envelope is deliberately fixed and rejects different or attacker-supplied parameter profiles:

- Passwords are normalized to Unicode NFC before derivation. New exports require at least 12 characters; users should generate and retain the password in a trusted password manager.
- Argon2id version 1.3 derives a 256-bit key with exactly 65,536 KiB (64 MiB) of memory, three iterations (`t=3`), and one lane (`p=1`).
- A cryptographically random 256-bit data-encryption key (DEK) encrypts the payload. The Argon2id-derived key wraps that random DEK with AES-256-GCM, binding the authenticated envelope header.
- The ZIP payload is processed as 1 MiB AES-256-GCM authenticated chunks with per-record metadata and header binding. An authenticated terminal record covers the total length, chunk count, and SHA-256 stream digest so truncation, reordering, and trailing records are rejected.
- Any transient plaintext ZIP is created only inside an app-owned temporary directory with complete file protection on iOS and owner-only permissions, is bounded before processing, and is removed when the operation ends. A launch-time scavenger removes protected workspaces left by a prior crashed process. The final plaintext package is never written beside the encrypted export.
- Imports and exports preflight protected temporary storage. Because the current verified package object materializes canonical JSON and portrait bytes, its default inner-ZIP ceiling is 512 MiB even though the envelope counters can represent more; raising that configurable limit is release-gated on a genuinely streaming inner package model and minimum-device memory tests.

Keepsake deliberately reports the same generic error for an incorrect password and a damaged encrypted archive. Passwords are not stored and cannot be recovered or reset; losing the password makes that archive unrecoverable.

The cryptographic/archive dependencies are exact-version pins: [`swift-sodium` 0.11.0](https://github.com/jedisct1/swift-sodium) under the ISC license and [`ZIPFoundation` 0.9.20](https://github.com/weichsel/ZIPFoundation) under the MIT license. Their complete notices ship in [`Resources/ThirdPartyNotices.txt`](Resources/ThirdPartyNotices.txt). Exact pins limit dependency drift, but they are not a security review. An independent audit of the envelope design, implementation, dependency source and binaries, failure behavior, and supported-device performance remains a release requirement before making production cryptographic-security claims.

### Run on your own iPhone

The app requires iOS 18 or later. A free Apple Account is enough for local, on-device testing. Testing iCloud synchronization requires a paid Apple Developer Program team because the build must be provisioned for the app's CloudKit container:

1. Open the Xcode project, then sign in under **Xcode → Settings → Apple Accounts**.
2. Connect and unlock the iPhone, trust the Mac when prompted, and select the phone in Xcode's run-destination picker.
3. Select the **Keepsake** target, open **Signing & Capabilities**, leave automatic signing enabled, and choose your team. Use the same team for **KeepsakeShare** and register the checked-in `group.com.zacrotech.RelationshipNotebook` App Group for both targets. For iCloud sync, use your paid team, register a new CloudKit container owned by that team, and set `CLOUDKIT_CONTAINER_IDENTIFIER` to its identifier. Keep this container dedicated to the stores managed by `NSPersistentCloudKitContainer`; do not reuse a container whose schema or records are managed by manual CloudKit code or another app. A free Personal Team can run a local-only build, but it may require replacing the App Group identifier and cannot sign the checked-in iCloud and Push Notifications entitlements: for that temporary local test, remove those two capabilities from the target and clear `CLOUDKIT_CONTAINER_IDENTIFIER`, then restore them before testing sync.
4. On the iPhone, enable **Settings → Privacy & Security → Developer Mode**, restart, and confirm. This option may appear only after Xcode starts pairing the device.
5. Return to Xcode and choose **Product → Run** (`⌘R`). Xcode signs, installs, and launches Keepsake on the phone.

A free Personal Team is appropriate for this app's local-only mode, but its App IDs, registered devices, and provisioning profiles expire after seven days, so reinstall from Xcode when needed. Apple documents Personal Team limits of 10 App IDs, three devices, and three installed apps per device. TestFlight, App Store distribution, and CloudKit provisioning require paid program membership and their own release setup.

For iCloud testing, run the signed development build on a device signed in to iCloud, open **Settings & Privacy**, find the **Notebook** sync status, check availability, and use the reviewed **Move this local notebook to iCloud…** flow. To explicitly create/update the development schema, add the `--initialize-cloudkit-schema` launch argument to the Xcode scheme for one signed Debug run, then remove it. Inspect the result in CloudKit Console, add the required indexes, and deploy that schema to production before TestFlight or App Store distribution. Promotion is a one-way release boundary: treat production record types, field names and types, and each field's CloudKit encryption state as immutable after promotion. Validate the complete schema first, then test with two physical devices on the same account and cover offline edits, deletes, portraits, account switching, quota exhaustion, and eventual convergence.

The same Notebook section reports **Background push registration**. It registers with APNs only while iCloud synchronization is enabled, retries a transient failure when the app next becomes active, and never logs or stores the device token. `NSPersistentCloudKitContainer` owns the CloudKit subscriptions and silent-push processing; the app deliberately has no developer-operated token database or custom APNs provider because visible connection reminders are calculated and scheduled on device. Test notification permission, foreground banners, lock-screen privacy, reminder taps, and two-device CloudKit wakeups on physical hardware—simulator delivery does not validate production APNs or CloudKit provisioning.

Keepsake ChatGPT testing requires an Apple Intelligence-compatible physical device on iOS 26 or later in a region where Apple Intelligence and the ChatGPT extension are available. It does not require Keepsake to hold Apple’s legacy native-PCC entitlement because the user’s Shortcuts workflow owns the **Use Model** action. Complete the in-app round-trip test, then manually inspect **Keepsake ChatGPT Connection** and confirm **Use Model → Extension Model (ChatGPT)** before testing with notebook context. No OpenAI API key or ChatGPT account is required by Keepsake, but the user must meet Apple’s age requirement and an edited Shortcut could use another model or service that the app cannot attest.

## Capability and release gates

The repository is safe and truthful when externally configured Apple services are unavailable. These capabilities require configuration or validation outside source code:

- **CloudKit release:** private-database mirroring, account isolation, local migration, status reporting, APNs launch registration, entitlements, and background remote notifications are implemented. A team owner must register a new container dedicated to the app's `NSPersistentCloudKitContainer` stores, sign a development build, verify the signed app's APNs/CloudKit entitlements, inspect the generated development schema, add required query indexes, promote it to production in CloudKit Console, and complete the real-device matrix above. Do not promote until the record types, fields, and CloudKit encryption choices are final, because those production schema decisions cannot be changed afterward. The app remains local and reports unavailability when those external prerequisites are absent.
- **Central Keepsake ChatGPT connection:** the two authenticated actions, explicit configured-Shortcut consent, challenge-tested setup, policy/expiry/replay checks, protected handoff store, Today integration, and contact-draft integration are implemented. Automated tests prove the app-owned handoff invariants but cannot prove the external editable **Keepsake ChatGPT Connection** Shortcut uses **Extension Model (ChatGPT)** or attest the account, actions, processing, retention, history, or quota. Release qualification requires an Apple Intelligence-compatible physical device on iOS/macOS 26 or later and manual tests for setup, local authentication, Extension Model selection, signed-out and signed-in ChatGPT extension states, age/region/service availability, added or reordered actions, cancellation, offline behavior, shortcut deletion/renaming, context changes, expiry, app termination, privacy disclosure, and English/Japanese copy.
- **Password-encrypted `.relationshipvault` archives:** import/export is implemented with the fixed Argon2id/AES-256-GCM profile documented above and exact dependency pins. Release remains gated on an independent cryptographic and dependency audit, cross-device interoperability and corruption testing, memory/performance validation on the minimum supported hardware, and review of localized password-loss and recovery messaging.
- **Share Extension and inbound files:** the extension target, App Group staging, file limits, protected writes, locked-safe queue, stale-partial cleanup, and review routing are implemented and simulator-buildable. Release qualification still requires signed-device tests from Photos, Files, Safari, Mail, and Notes, including cancellation, app-not-foregrounded behavior, protected-data lock state, corrupt files, and disk exhaustion.
- **Static profile snapshots:** recipient-controlled copies cannot be remotely erased. Live `CKShare` cards remain a separately gated post-v1 capability.
- **External communication apps:** installed-app behavior, signed-in identity, delivery, and final message content are controlled by those apps. Keepsake records only the evidence state it can prove or the user explicitly confirms.

Do not market the current CloudKit protection as unconditional end-to-end encryption. Its guarantees depend on Apple’s iCloud and Advanced Data Protection configuration unless a separately reviewed app-layer encryption design is added.
